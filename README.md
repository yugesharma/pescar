# PescaMare

Planning tool for pescatourism, piloted in the Azores and covering every EU fishing harbour, built on Copernicus Marine and EU fisheries data
(Copernicus Marine Service Hackathon 2026). Design: [DESIGN.md](DESIGN.md), terms: [GLOSSARY.md](GLOSSARY.md),
decisions: [docs/adr/](docs/adr/), background: [pescatourism_project.md](pescatourism_project.md).

## Run

Needs [uv](https://docs.astral.sh/uv/), Node 20+, a Copernicus Marine login (`uv run copernicusmarine login`), and a free
Global Fishing Watch API token ([globalfishingwatch.org/our-apis/tokens](https://globalfishingwatch.org/our-apis/tokens),
non-commercial use) in `.env` as `GFW_API_KEY=...` (git-ignored); `build.py` uses it for fishing pressure, and the API for the dark-vessel layer (fetched on first use, rechecked daily, cached in `data/cache/dark/`).

```sh
cd backend
uv run python build.py            # write ../data/pescamare.db: first run ~1 h (waves for ~2,000 harbours,
                                  # OSM for 22 countries), then ~2 min (only the 11 pilot harbours refetch)
uv run uvicorn api:app            # API on :8000
cd ../frontend && npm install && npm run dev   # app on :5173, proxies /api to :8000
```

Frontend check (from `frontend/`): `node geo.check.ts` (range and bearing maths).

The chlorophyll, sea temperature and wave layers load live in the browser from the Copernicus Marine WMTS (no login, no build step), so they need network access.

Self-checks (no network, from `backend/`): `uv run python scoring.py`, and `--test` on `waves.py`, `build.py`, `community.py`, `pressure.py`, `species.py`, `habitat.py`, `fronts.py`, `dark.py`, `api.py` (in-process requests against a temporary `user.db`; needs a built `pescamare.db`).

Demo data for Monitor (from `backend/`): `uv run python api.py --demo` seeds Ponta Delgada and Vila Franca do Campo with generated trips flagged `demo`; rerunning replaces them and leaves real validations alone.

## Layout

- `backend/`: Python data pipeline (`build.py` and one module per factor), pure scoring (`scoring.py`), API (`api.py`).
- `frontend/`: React + TypeScript + Vite + MapLibre app.
- `data/`: inputs and the generated database, shared by both (below).
- `.env` (root, git-ignored): API tokens.

## Data in `data/`

- `fleet_EU_current.csv`: EU Fleet Register, current records of all EU vessels.
- `unlocode.csv`: UN/LOCODE code list (GitHub mirror `datasets/un-locode`).
- `pescamare.db`, `fronts.png` (fish fronts map image): generated by `build.py`, not committed.
- `user.db`: investment proposals, validations and trips, written by the API (created on first use, not committed). `build.py` never touches it, because it replaces `pescamare.db` whole.
- `cache/`: not committed; delete a file to refetch it.
  - `osm_<CC>.json`: raw OpenStreetMap responses per country.
  - `geonames/<CC>.zip`: GeoNames country dumps, to place ports without UN/LOCODE coordinates.
  - `nuts2.geojson`: Eurostat NUTS 2 regions (GISCO 2024, 1:1M).
  - `waves/<code>.json`: wave results per non-pilot harbour (history up to the fetch date).
  - `gfw_effort_<year>.json`: Global Fishing Watch AIS fishing effort for the pilot box.
  - `ices/`: ICES SAG stock lists and status per assessment.
  - `aquamaps/<SpecID>.html`: AquaMaps envelope pages (species temperature ranges).
  - `thetao_monthly.nc`: Copernicus monthly sea temperature by depth for the pilot box, mean per month 2023–2025.
  - `bathy/<code>.tif`: EMODnet Bathymetry around each pilot harbour.
